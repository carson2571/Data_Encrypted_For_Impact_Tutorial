Data Encrypted for Impact

How ransomware turns a company's own files into a hostage — and what defenders can do about it. Written for someone who is smart but new to security.

01

Introduction and Overview

Data Encrypted for Impact is what happens when an attacker scrambles the data on a victim's computers so the owner can no longer use it. The attacker keeps the only way to unscramble it and offers to "sell it back." This is the core action behind ransomware — malicious software that holds data hostage for payment.

Key terms

Encryption
Mathematically scrambling data so it can only be read by someone with the correct key. Normally a security tool — here it is used as a weapon.
Key
A secret value (a long random number) that locks and unlocks encrypted data. No key, no data.
Ransom note
A message the attacker leaves behind explaining what happened and how to pay.
Impact
In MITRE ATT&CK, the attacker's final goal: disrupting, destroying, or manipulating systems and data.

Think of it like a burglar who doesn't steal your stuff — they put a padlock on every drawer in your house and mail you a bill for the key. Everything is still there; you just can't open any of it.

02

Why Attackers Use This Technique

Adversarial mindset question: what problem does this solve for the attacker? Stealing data and selling it is slow and uncertain. Encrypting data turns the victim into the buyer — and the victim is desperate.

💰 Direct Money

The victim pays the attacker directly, usually in cryptocurrency, which is hard to trace and fast to move.

⏱️ Time Pressure

A hospital, pipeline, or school that can't operate loses money and trust every hour. Downtime pushes people to pay quickly instead of thinking.

🔐 Math Is on Their Side

Modern encryption, done correctly, can't be broken by brute force. If backups fail, the attacker's key may be the only way back.

🧲 Double Extortion

Many groups steal a copy of the data before encrypting it, then threaten to leak it. Even victims with good backups now have a reason to pay.

🏭 It Scales

"Ransomware-as-a-Service" (RaaS) groups rent their tools to affiliates and split the profits, like a criminal franchise.

💥 Sometimes: Pure Destruction

Some "ransomware," like NotPetya (2017), had no working way to decrypt. Encryption was just a disguise for wiping data.

03

Prerequisites and Assumptions

Encryption is the last step. Before an attacker can lock anything, several things already have to be true. Each one is also a place a defender can stop them.

What the Attacker Needs

  • A foothold — a way in, such as a stolen password, a phishing email, or an unpatched server.
  • Enough privileges — permission to write to the files that matter (often administrator or domain admin rights).
  • Reach — access to file shares, servers, virtual machines, or cloud storage, not just one laptop.
  • Time undetected — attackers often spend days or weeks inside a network before encrypting.

What the Attack Assumes About the Victim

  • Backups are missing, old, untested, or reachable from the same network (so they get encrypted too).
  • Nobody is watching for unusual activity, like thousands of files changing in minutes.
  • Accounts lack multi-factor authentication (MFA), so one stolen password is enough.
  • The organization values fast recovery more than the ransom amount.

04

Step-by-Step: How the Attack Works

Here is a typical modern ransomware intrusion, from first access to ransom note. Click a step to expand it. The orange step is T1486 itself; the others are the steps that make it possible.

  1. The attacker gains entry using a phished login, a password leaked in an old breach, an exposed remote-access service (like VPN or RDP), or an unpatched vulnerability.

  2. They map the network: which servers hold important data, where backups live, and who the administrators are. They move from machine to machine and try to gain admin rights.

  3. In double-extortion attacks, they upload sensitive files to a server they control. This becomes leverage: "pay, or we publish."

  4. They delete local backups and Windows "shadow copies" (automatic restore points), disable recovery options, and stop services like databases and backup agents so files aren't locked open. This step is closely tied to encryption — it's how attackers make sure the victim can't simply roll back.

  5. Ransomware runs on many machines at once, often at night or on a weekend when fewer people are watching. It walks through folders, encrypts each file, and frequently renames it with a new extension (for example report.docx → report.docx.locked). It usually skips system files so the computer still boots — the victim needs a working machine to read the ransom note.

    See the diagram below for how the files are locked.

  6. A text or HTML file appears in every folder (and sometimes as the desktop wallpaper) with instructions, a deadline, and a payment address or chat portal.

Inside Step 5: Hybrid Encryption

Encrypting thousands of files needs to be fast, but the attacker also needs to be the only one who can undo it. Ransomware solves both problems by combining two kinds of encryption:

Symmetric encryption
One key both locks and unlocks (e.g., AES). Very fast. Like a normal house key.
Asymmetric encryption
Two linked keys (e.g., RSA): a public key that can only lock, and a private key that can unlock. Like a mailbox slot anyone can drop into, but only the owner can open.

This is exactly what the ransom "buys."

Why not just find the file key on the disk? Well-built ransomware erases it from memory after use. Poorly built ransomware sometimes doesn't — which is why security researchers have released free decryptors for some families (see No More Ransom).

05

Real-World Example: Colonial Pipeline (2021)

WhenMay 7, 2021
WhoDarkSide (RaaS group)
VictimLargest refined-fuel pipeline in the U.S.
Ransom paid75 BTC (~$4.4M)
  1. Entry: Attackers logged into an old VPN account using a password that had been exposed. The account did not require multi-factor authentication.
  2. Impact: DarkSide encrypted business (IT) systems, including billing, and stole roughly 100 GB of data.
  3. Response: Colonial shut down the pipeline itself as a precaution, since it couldn't be sure the operational systems were safe and couldn't bill customers.
  4. Fallout: Fuel deliveries along the East Coast were disrupted for about five days, causing panic buying and shortages.
  5. Aftermath: The U.S. Department of Justice later recovered about 63.7 BTC of the ransom.

Adversarial lesson

The ransomware never touched the pipeline's control systems — encrypting the business side was enough to stop fuel moving. One unused account without MFA led to a national news event.

Also Worth Knowing: WannaCry (2017)

WannaCry spread on its own like a worm, using a Windows file-sharing vulnerability (EternalBlue, patched by Microsoft in March 2017 as MS17-010). In May 2017 it hit hundreds of thousands of computers in over 150 countries, including the UK's National Health Service, demanding about $300 in Bitcoin per machine. It shows the same technique delivered a completely different way: no stolen password, just an unpatched system.

07

Detection Opportunities

Encryption is loud. Thousands of files change in minutes, and the warning signs before it are louder still — if someone is listening.

📂 Mass File Changes

One process modifying or renaming hundreds of files per minute, or many files suddenly getting the same new extension.

Data source: File modification

🎲 Random-Looking Contents

Encrypted data looks completely random (high entropy). A document that suddenly turns into noise is a red flag.

Data source: File content

🧯 Recovery Tampering

Commands that delete shadow copies or turn off Windows recovery — rarely legitimate, very common right before encryption.

Data source: Command execution

🪤 Canary Files

Decoy files placed in shared folders that nobody should ever touch. If one changes, something is encrypting everything.

Technique: Deception

🗒️ Ransom Notes

The same new text or HTML file appearing in many directories at once.

Data source: File creation

🌐 Earlier Clues

Odd logins (new location, odd hours), large outbound uploads, and new admin tools appearing — often days before encryption.

Data source: Logon session, network traffic

08

Mitigations and Defenses

No single control stops ransomware. Defenders layer protections so that each step in section 04 has a chance to fail.

1 · Offline, Tested Backups

The single most important defense. Follow the 3-2-1 rule: 3 copies, on 2 types of media, with 1 offline or immutable (can't be changed or deleted, even by an admin). Practice restoring — an untested backup is a hope, not a plan.

2 · MFA Everywhere

Especially on VPN, remote desktop, email, and admin accounts. This alone would likely have stopped the Colonial Pipeline entry.

3 · Patch Quickly

WannaCry used a bug that had been patched two months earlier. Prioritize internet-facing systems.

4 · Least Privilege

Users and service accounts should only be able to change the files they truly need. Fewer admin accounts means less to encrypt.

5 · Network Segmentation

Separate networks so one infected laptop can't reach every server — and backups are never reachable from the main network.

6 · Endpoint Detection (EDR)

Security software that watches behavior and can kill a process that starts mass-encrypting files.

7 · Incident Response Plan

Decide before an attack who to call, how to isolate systems, and how to restore. CISA and the FBI recommend reporting attacks and generally discourage paying.

09

Key Takeaways

  • T1486 uses encryption — normally a protective tool — to deny victims access to their own data.
  • Encryption is the final step. Attackers need access, privileges, and time first, and every one of those is a chance to catch them.
  • Hybrid encryption makes ransomware both fast and practically impossible to reverse without the attacker's private key.
  • Double extortion means backups alone don't remove all pressure — preventing data theft matters too.
  • The best defense is boring: offline tested backups, MFA, patching, least privilege, and monitoring.
